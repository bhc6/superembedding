# Step 250 的冻结 choice 专精补充

目的：检验通用训练后的模型，是否仍能在不改权重的情况下，通过任务固定方向适应 ChartQA 与 VSR。观察到这两个来源较差之后才提出，因此属于探索性验证集分析，不能叫未见任务泛化或确认性测试。

在所有新提示结果产生前，封存 `sources/choice_adaptation_v5.json`。ChartQA 65 条、VSR 110 条，沿用同一批输入、候选、正例规则和排序。Step 250 完整 bundle、重建 Step 0、原始预训练 branch 向量作为对照。Step 0 原始保存文件已覆盖，必须保留“重建”限定。

三个方向组：

- 原始四个通用方向。
- 通用方向同义改写，控制措辞改变本身。
- 每个任务一组预先固定的专精方向，不按单条查询或答案生成，不在看到结果后继续改写并只报最好版本。

ChartQA 的四方向分别聚焦系列/图例、颜色与标记、坐标轴与对齐、数值/单位/运算。VSR 聚焦主语和参照物、实体辨识、带方向的空间关系、支持或反驳关系的视觉证据。保持四个 slot、原槽位语义顺序、相同共享 projection、相同总维度、原顶层 instruction、输入问句和答案不变。

每组同时评测两个索引设置：双方使用新方向（每任务重建候选库），只改查询侧（复用原方向候选向量）。前者支持任务条件化的缓存；后者更直接检验固定记忆库能否适应新的检索指令。这里的候选是答案文本，并非一般的图片记忆库，不能把结果直接推广到所有记忆检索场景。

所有组都有完整图文查询和 text-only，复用相同候选向量。报告全部结果及成对查询 bootstrap 区间；VSR 额外报告 balanced accuracy、混淆矩阵、预测类别比例，防止变成更偏向多数类。比较专精方向相对原方向的提升、视觉贡献变化、Step 250 与 Step 0 的提示收益差。分问题类型按现有固定文字规则，不冒充官方分类。

判读：若完整输入提升而 text-only 同步提升，首先考虑语言匹配改善；若 balanced accuracy 不升但总分升，首先考虑类别偏置。若仅双方重编码有效，结论要注明重建索引成本。若 raw 与 Step 0 的提升也一样明显，不能归因于我们的训练。即使所有检查通过，仍需把同一组方向封存后转到独立未见数据，才能支持更强泛化结论。

执行采用 CPU FP32，不抢占长训/优先基线的 GPU。先封存协议，等待正在执行的本地 Qwen2B 释放 CPU 内存后启动；分片按模型、输入、方向、完整协议哈希分别缓存，支持相同命令断点继续。各组基线在相同精度下重新计算，不把 FP32 与训练日志 BF16 的差作为提示收益。原正式模型和最终评测流程不被替换。
