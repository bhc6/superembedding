# 多域扩量实验协议 v3

本协议在 v3 训练和测试前固定。v0.1.0 是已经公开的先导实验，不与新测试混为同一统计样本。本轮全部训练、审计、结果及模型导出完成后统一提交与发布，不中途 push。

## 数据与任务

- Fashion expanded：官方目录属性颜色、商品类型、目录受众，10,853 张；训练 7,894、验证 1,184、测试 1,775。所有旧先导图像所在重复组件只能进入训练。解码后精确重复或同时满足 dHash 距离 ≤4、32×32 RGB 平均绝对差 ≤5/255 的图像连成组件后划分。此方法是重复图像启发式，不保证剔除全部同款商品。
- CUB-200-2011：全部官方 11,788 图，精确去重后 11,787；保留官方 5,794 测试图，官方训练部分按物种分层取 20% 验证，训练/验证为 4,793/1,200。使用 primary color、bill shape、wing shape 三组人工属性。保留置信度 ≥3 的全部正值；没有这样的值表示未观察，不能当作一个负类。数据只限非商业研究及教育，不发布原始图像。
- DTD r1.0.1：全部 5,640 图，使用官方 split 1，原始训练/验证/测试各 1,880。去除 17 个解码后精确重复图后共 5,623 图，训练/验证/测试为 1,874/1,872/1,877；遇到重复优先保留测试，再保留验证。主要检索标签为 47 种 key texture，次要评测用人工 joint texture annotations。明确不等同于官方 10-split 分类基准。

各数据集固定验证和测试集。训练按第一属性已观察值集合分层，以各层随机次序的分位点交错排列，尽量保持各档标签比例，使用嵌套 25%/50%/100% 子集；三阶段分别从同一个种子初始化，不从上阶段继续训练，从而避免把额外训练步数误作数据量收益。本轮检验逐级增加可用数据的效果；不声称已经训练跨域统一 head。

## 架构、对照与预算

OmniJev-0.8B-v1.1、禁用其 LoRA 的 backbone 消融、官方 FLAIR merged30m。模型 revision 和提取设置固定、每张图预编码一次，与检索查询无关。禁用 LoRA 仍保留 OmniJev 特殊 token，不称为原生 Qwen embedding。

OmniJev/base 使用同布局图像最多 4 张一批的编码；图像之间和选项之间仍保留独立 attention/KV/recurrent 状态。与官方逐图路径比较，训练图上的最低余弦相似度必须 ≥0.999。BF16 批量矩阵运算不承诺逐位相同；所有正式 OmniJev/base 特征统一重算，不复用逐图先导缓存。编码分辨率为 max_pixels=65,536；FLAIR 采用官方 224px 变换。原逐图缓存保留在 runs/v3_serial_preserved。小样本批量吞吐测试受到其他进程影响，不能当作独占 GPU 的标准性能榜单。

每属性 256 维。完整训练规模比较 raw、frozen gate、tuned gate、residual、joint concat、joint output equal、joint output small 共七种 OmniJev 架构/训练设置（raw 和 joint concat 的网络相同、训练目标不同）。前两档比较 raw 与三个 joint 架构。等维 output 是 K×256 → K×256；压缩 output 是 K×256 →256，DTD 单属性为 256→128。前三种 joint 架构均使用相同属性+交集三元组损失，公平比较是否需要最终投影。FLAIR 全规模也跑这三个 joint 架构，全部规模都有 raw；base 全规模及扩量都跑 raw。

每格三个种子 17/42/91，学习率 1e-4/1e-3，共 432 次训练。每次固定 1,000 optimizer updates、每损失 64 triplets、margin .2、AdamW weight decay .01、梯度裁剪 1。joint 方法每次另外 64 个交集 triplets，计算预算比 attribute-only 多，报告中明确区分。按同架构同规模三个种子平均验证分数选一个学习率；验证每 250 步，保留最优步（含 step 0）。不保证 1,000 步充分收敛，报告最优步和末端趋势。

raw/gated/residual 的验证目标为属性 macro mAP；joint 方法为属性与全交集 mAP 的平均。不根据测试选择架构、步数、学习率或重跑方向。各档固定步数用于比较数据效率，不宣称等 epoch 或等 FLOPs。所有原始 gate 来自官方 decision head。

## 多值与缺失的统一处理

单属性正样本：两图至少共享一个已观察值；交集正样本：每个指定属性均共享已观察值。查询或候选在指定属性缺失时排除该对；排除自身；无正例查询不进入 mAP，同时报告覆盖率。负例表示已观察正值集合不相交，不声称标签穷尽了所有可能的视觉属性。CUB 这种检索协议是自定义属性任务，不直接对比物种分类准确率。

主指标为属性 macro mAP、联合 mAP；次指标为 R@1、R@5、双属性交集。mAP 按所有有效正例计算，不截断 top-k。按三个训练种子报告均值、标准差；种子方差不代表数据抽样置信区间。不同领域的类别基率不同，不把跨域原始 mAP 直接当作难度比较。

压缩后的全局向量服务全交集检索。若需要按任意属性选择方向，仍须存储 slot 向量；不能把 256 维 global 的容量节省宣称为完整属性选择记忆的容量节省。

## 恢复、审计与发布

每 100 步及正常中断保存 last checkpoint，包括 optimizer、局部/Python/torch/CUDA RNG、日志窗口累计量、配置及完整数据/特征指纹；另存 best head。队列重启跳过已验证完成实验。缓存逐图原子写入；FLAIR 复用先导缓存须逐条比对图像 hash、属性 basis 和模型设置。所有旧 checkpoint 保留。相同特征/模型 revision 的缓存允许路径搬迁，不以机器绝对路径作为数据身份。

先核对数据隔离、标签、配置、完成矩阵、恢复等价，再解封测试。发布代码、划分清单、完整验证网格、测试结果和可加载 head/checkpoint；第三方图片、原始 backbone 权重不随仓库上传。本轮主实验训练投影/门控 head，backbone 冻结；先导 LoRA 真图训练的负结果保留，不冒称本轮已做大规模端到端训练或教师敏感性蒸馏。
